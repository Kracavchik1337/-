# Документация информационной системы автоматизации пекарни-кондитерской «Tasty Buns»

Данный документ содержит техническое описание базы данных (ER-диаграммы) и пользовательского интерфейса (макетов приложения) для автоматизации бизнес-процессов пекарни «Tasty Buns».

---

## 1. Описание логической структуры базы данных (ER-диаграмма)

База данных спроектирована для обеспечения полного цикла учета: от поступления сырья и управления рецептами до производства, списания брака и розничных продаж. В системе выделено 11 ключевых сущностей:

### Блок управления персоналом
*   **Employee (Сотрудники):** Хранит личные данные персонала.
    *   `employee_id` (PK) — уникальный идентификатор сотрудника.
    *   Поля: `full_name` (ФИО), `position` (должность — например, пекарь, кассир, менеджер), `phone` (номер телефона), `hire_date` (дата приема на работу) и `status` (активен/уволен).

### Блок складского учета и ингредиентов
*   **RawMaterial (Сырье / Ингредиенты):** Справочник всех используемых продуктов (мука, сахар, дрожжи и т.д.).
    *   `material_id` (PK) — уникальный код ингредиента.
    *   Поля: `name` (наименование), `unit` (единица измерения: кг, л, шт), `current_stock` (текущий остаток на складе), `unit_price` (себестоимость за единицу), `min_threshold` (критический остаток для автозаказа).
*   **Supply (Поставки):** Документ поступления сырья от поставщиков. Связан с сотрудником, принявшим поставку.
*   **SupplyItem (Позиции поставки):** Таблица-связка (многие-ко-многим) между `Supply` и `RawMaterial`. Фиксирует, какое количество (`quantity`) конкретного сырья и по какой цене (`purchase_price`) было закуплено в рамках конкретной поставки.

### Блок рецептур и производства
*   **Product (Готовая продукция):** Ассортимент пекарни (выпечка, хлеб, десерты).
    *   `product_id` (PK) — уникальный код товара.
    *   Поля: `name` (название изделия), `category` (категория: Хлеб, Булочки и т.д.), `price` (розничная цена), `shelf_life_hours` (срок годности в часах), `status` (в продаже / архив), `stock_quantity` (текущее количество готовых изделий на витрине).
*   **Recipe (Рецепты):** Технологические карты для производства. Связана соотношением «один-к-одному» или «один-ко многим» с сущностью `Product`. Содержит текстовое поле `instructions` (шаги приготовления) и `output_quantity` (нормативный выход готовой продукции с одной раскладки).
*   **RecipeItem (Состав рецепта):** Связывает `Recipe` и `RawMaterial`. Определяет количество (`quantity`) конкретного сырья, необходимое для приготовления изделия.
*   **Batch (Партия / Варка):** Журнал производства готовой продукции. Фиксирует дату/время выпекания (`produced_at`), объем получившейся партии (`quantity_produced`), статус (готово, в процессе) и сотрудника-пекаря (`employee_id`).
*   **BatchMaterial (Расход сырья на партию):** Автоматически списывает ингредиенты (`quantity_used`) со склада `RawMaterial` под конкретную варку/партию `Batch` согласно рецептуре.

### Блок продаж и списаний
*   **WriteOff (Списания):** Учет брака, порчи сырья или непроданной вовремя готовой продукции с истекшим сроком годности. Фиксирует `reason` (причину), дату и ответственного сотрудника. Может списывать как сырье (`material_id`), так и готовый продукт (`product_id`).
*   **Sale (Продажи / Чеки):** Заголовок продажи. Содержит дату/время (`sold_at`), общую сумму (`total_amount`), способ оплаты (`payment_method`: наличные, карта, СБП) и ID кассира.
*   **SaleItem (Позиции чека):** Содержимое продаж. Связывает `Sale` с `Product`, фиксируя количество купленного товара (`quantity`) и цену на момент продажи (`unit_price`).

## 2. Описание макетов интерфейса приложения (UI/UX)

Разработан клиентский интерфейс мобильного приложения пекарни в темной современной стилистике с фоновым паттерном в виде графических элементов выпечки.

### Экран 1: Авторизация (Вход в систему)
*   **Назначение:** Идентификация клиента для доступа к программе лояльности, истории заказов и корзине.
*   **Элементы интерфейса:**
    *   Логотип пекарни с каллиграфическим шрифтом **«Tasty Buns»**.
    *   Заголовок формы: **«Вход»**.
    *   Поле ввода номера телефона с готовой маской: `7 (xxx) xxx-xx-xx`. Позволяет избежать ошибок при вводе.
    *   Поле ввода пароля: **«Введите пароль»** (с возможностью скрытия символов).
    *   Кнопка/ссылка перехода: **«Зарегистрироваться»** для новых пользователей.

### Экран 2: Каталог товаров (Главный экран)
*   **Назначение:** Демонстрация ассортимента пекарни, навигация по категориям и выбор позиций.
*   **Элементы интерфейса:**
    *   **Промо-баннер:** Яркое широкоформатное изображение свежевыпеченного хлеба/багетов в руках пекаря для привлечения визуального внимания.
    *   **Панель категорий (Табы):** Горизонтальный скролл-фильтр для быстрого переключения между типами продукции. Активный таб подсвечен серым фоном. Доступные категории:
        *   `Хлеб` (активен на макете)
        *   `Булочки`
        *   `Сладкое`
        *   `Пироги`
    *   **Сетка товаров (Grid):** Плиточное отображение карточек продуктов текущей категории. Каждая карточка включает:
        1. Качественную фотографию изделия.
        2. Название товара в нижнем регистре (стилистическое решение интерфейса): *«французский багет»*, *«хлеб пшеничный»*, *«хлеб чиабатт»*.
        3. Четко выделенный ценник, например: *«цена: 200руб»*, *«цена: 120руб»*.

## 3. Взаимосвязь интерфейса и базы данных (Интеграция)

Приложение напрямую зависит от спроектированной ER-структуры. Ниже приведен пример того, как элементы макета связаны с таблицами БД:

1.  **Категории на макете:** Формируются на основе уникальных значений поля `category` из таблицы `Product`.
2.  **Карточки товаров:** Динамически подгружаются из таблицы `Product`. Название на макете берется из поля `name`, изображение привязывается к `product_id`, а ценник выводит значение поля `price`.
3.  **Логика отображения (Остатки):** В интерфейс выводятся только те карточки, у которых `status = 'в продаже'` и `stock_quantity > 0` (то есть товар физически есть на витрине пекарни).

### Пример SQL-запроса для генерации экрана «Хлеб»:
```sql
SELECT product_id, name, price, category 
FROM Product 
WHERE category = 'Хлеб' 
  AND status = 'Active' 
  AND stock_quantity > 0;
```
